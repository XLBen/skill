# 竣工复盘协议（retro-protocol）

> 何时读：选择做复盘时，在完成事件之前；完成后补充观察也必须遵守历史不可变规则。

竣工不是终点——评审和施工过程里踩过的坑，不沉淀就会在下一个项目重踩一次。复盘把"这次为什么卡"变成"下次立项就写对"。

## 何时做

- 复盘可选，不是完成门槛；用户要求或项目规则启用时，读 build-log 全部"待议"与重试记录。
- 包内记录必须在 `finish-plan` 之前追加；完成后新增观察记在包外的新记录中，不修改历史包。
- CR 关闭（closed）超过 2 单时，在竣工复盘中重点总结这些变更。
- 未启用或用户说"不复盘"时跳过，交接照常输出，不为取得跳过许可打断交付。

## 输入（只读这些来源，不靠回忆）

| 来源 | 找什么 |
|---|---|
| `docs/review-log.md` | 哪几类问题反复出现（≥2 轮同攻击面）；哪些硬伤暴露得太晚 |
| `docs/build-log.md` | 重试 ≥2 次的步骤；全部"待议"条目及其去向 |
| `docs/change-orders.md` | 每个 CR 的触发事实、影响闭包与最终处置；这是 CR 状态唯一来源 |
| `check.py reconcile` 输出 | 竣工当时的覆盖矩阵快照：`stale_evidence_events`、`dormant_variants`、converge-audit 议题——这些是"结构闭合但语义可疑"的高发区 |
| `docs/mvp-observation.md`（v0.1） | Phase 0、切片预算、真实验收、失败签名、熔断、作者隔离和 BA-01 结果 |
| `docs/slice-increments/`（如有） | 正常增量与 CR 的边界、每次增量的验证和未重放步骤 |

## 产出（只保留有证据的适用条目）

```markdown
## 复盘 — <项目名>（日期）
### 1. 章程增补建议（→ docs/review-charter.md）
- 建议新增 C-xx：<这次晚发现的硬伤，写成可判定条目>
### 2. 契约模板偏差（→ 本次记录，供下次立项注意）
- <如：V-01 验证写成了存在性检查而非行为检查，导致 S-04 返工>
- <如：第三次同签名失败后仍发生第四次重试，需把提示层规则下沉到引擎>
### 3. 施工程序问题（→ 如属本 skill 缺陷，向 skill 维护者反馈）
- <如：验收命令依赖了未来步骤的产物，规划时应拆步>
```

## 规则

1. 每条建议必须能追溯到具体事件（轮次/步骤/CR 编号），不许空谈。
2. 章程增补是**建议**：展示给用户，用户确认后才写入 `docs/review-charter.md`；未确认的留在复盘记录里。
3. 复盘不改任何已验收的东西。当前未完成包的缺陷走 CR；已完成 Audited 包的缺陷走新的 FIX 替代包，保留原包不变。
4. 仅在做了复盘时，交接中链接实际记录位置；未做不生成占位清单。可用结果与运行说明仍按 mvp-delivery 的交付要求输出。
