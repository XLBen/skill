# Debug：先复现，再修复

## 1. 复现
- 找到能稳定触发问题的最小命令或输入，记录确切的错误文本和退出码。
- 复现不了：先缩小条件（数据、顺序、环境），不要凭猜测修改。

## 2. 定位
- 读真实的代码和日志，从出错的位置沿调用链往回找，找到错误值第一次出现的地方。
- 找一条正常的路径（另一个输入、旧版本），对比它和失败路径的差别。
- 用一句话写出结论：“问题出在 X，因为 Y 已经排除（依据：…）”。

## 3. 确认根因
- 修改之前，先用一个最小实验证明根因（加一行打印、换一个输入、单独运行那个函数）。
- 一次只改一个变量。改了好几处才“好了”，就说明还没找到根因。
- 说“环境问题/权限问题/依赖版本问题”之前，要先有实验证据。

## 4. 修复并验证
- 在根因所在的层做最小修复。不要在下游加 try/except 或空值检查来掩盖问题。
- 原来的复现命令现在通过；再运行受影响部分的测试。
- 能稳定复现的缺陷，补一个回归测试。
- 检查同样的错误写法在别处有没有出现。

同一个错误连续 3 次修不好，停下来，把已经排除的东西和目前的证据告诉用户，换一种思路。

## 汇报
`根因: <已证实的一句话，或“未确认”> | 依据: <实验或日志> | 修复: <改了什么> | 验证: <命令和结果>`
