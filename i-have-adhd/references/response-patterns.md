# Response Patterns

这些模板只约束用户看到的内容。完整的验收事实使用 `SKILL.md` 的
`ACCEPTANCE_HANDOFF` 传给 reviewer/PUA。

## Progress

```text
状态：<已完成的一个具体动作>。
正在做：<当前一个动作>。
```

适用：实现中有真实进展，但没有阶段性通过结论。不要把“正在验收”写成“已通过”。

## Acceptance Preview

```text
当前阶段：<stage-id>
已具备：<一到三项事实>
正在验收：<一到三项检查>
下一步：<reviewer 检查／补验证／等待一个决定>
```

适用：准备调用 reviewer 或已有 engine/owner gate。若本轮没有实质进展，省略消息。

## Delivery

```text
结果：<第一行直接说明用户现在得到什么>
验证：<最关键的命令、输出或 owner 记录>
位置：<文件、入口、URL 或调用方式>
限制：<剩余未验证范围；没有则省略>
下一步：<唯一具体动作；没有则结束>
```

只列影响使用或完成判断的限制。不要用“全部完成”覆盖未验证边界。

## Blocker

```text
阻塞：<可核对事实>
已排除：<已执行的检查>
需要：<最小决定、授权或外部条件>
下一步：<解除后继续的位置>
```

## Error

```text
失败：<命令或文件位置>
预期/实际：<expected> / <actual>
原因：<已确认原因；未知就写“原因未确认”>
正在做：<一个具体的修复或区分性探针>
```

## Rules

- 多于一个用户动作时编号，每步只放一个边界动作。
- 用户只需要做一个决定时，不列无关选项。
- 需要完整证据时引用路径/命令，不把原始长日志直接塞进摘要。
- 最后一行给唯一下一步；没有下一步时不要加客套结束语。
