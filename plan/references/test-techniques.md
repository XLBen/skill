# 按风险选测试方法

只在简报或错误策略里确实有对应风险时使用。这张表选的是**测试方法**，不增加产品需求；
每个用到的方法都要对应到一条验收样例或错误策略条目。

| 风险 | 方法 | 最小做法 |
|---|---|---|
| 序列化 / 转换 | 往返性质 | 生成多种输入，断言 解析(输出(x)) == x，重复执行结果不变 |
| 不可信或格式错误的输入 | 边界与畸形输入 | 空、超长、错误编码、缺字段；断言按错误策略报错而不是崩溃或静默通过 |
| 接口或数据格式变化 | 契约测试 | 用消费方的期望检查生产方的真实输出 |
| 重复执行 / 重试 | 幂等 | 同一操作执行两次，断言状态和输出与执行一次相同 |
| 失败与恢复 | 故障注入 | 中途抛异常或超时，断言回滚或保持旧结果 |
| 并发 | 交错执行 | 并发或重复调用后，断言约定的不变量仍成立 |
| 数据迁移 | 对账 | 迁移前后行数和校验和一致；回滚路径也跑一次 |
| 权限 / 安全边界 | 反向测试 | 未授权请求被拒绝 |

规则：
- 测试必须能在缺陷存在时失败。写完后临时改坏一处代码，确认测试会变红，再改回来。
- 不需要每一行都用；只选与本项目风险对应的行。
