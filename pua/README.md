# PUA Acceptance Skill

这是 [tanweai/pua](https://github.com/tanweai/pua) 的本地适配版，用于本仓库的
workflow 验收，而不是新增公开命令或替代引擎 gate。

## 用途

PUA 在每个阶段验收前做一次主动质询：

- 证据是否来自当前制品，而不是口头结论；
- 事实是否经过工具验证，而不是把问题甩给环境或用户；
- 是否检查了同一根因、接口或受影响调用链的同类问题；
- 重复失败时是否更换了本质不同的方法；
- 真正需要 owner 或外部条件时，是否带证据等待或升级。

核心话术保留原版的“证据呢”“别在原地打转”“隔壁 agent 一次就过了”等风格，
但每句都绑定到检查、命令、输出或明确交接动作。正常任务不会因为话术而增加无限复查。

## 集成方式

`SKILL.md` 是入口。各阶段在自己的验收章节显式加载本 skill，并按
`references/stage-checks.md` 索引中 `stage_id` 对应的卡执行：

```text
阶段产物就绪
  -> PUA 阶段检查
  -> 既有 engine/reviewer/owner gate
  -> 正常交接、修复复验、等待决定或证据化阻塞
```

没有新增 `/pua` 命令，没有新增持久状态文件，也没有改变现有 goal、PLAN、ledger
或 `check.py` 的 schema。检查结果通过现有阶段交接和升级记录返回。

## 边界

PUA 只约束 agent 的执行质量：不能伪造成功、代答 owner、绕过权限或继续无限重试。
真实阻塞仍然必须如实报告。它不把“更努力”当作新的验收条件，也不把工具调用次数
当作完成度。
