# 项目答辩章程模板（charter-templates）

导师的攻击面矩阵是通用的；章程是**项目自己加的硬伤标准**——相当于给英语写的单元测试：每条都必须可判定通过/不通过，不许写"要有良好体验"这种无法判定的句子。

## 怎么用

1. 挑一个最接近项目类型的模板，复制到目标项目 `docs/defense-charter.md`。
2. 删掉不适用的条目，按项目改写措辞——**保留编号 C-xx**，导师提问引用。
3. 加你自己领域里的死线（例：游戏缺帧率预算 = 硬伤）。
4. 不确定就先空着，答辩第一轮后把导师追问出的问题沉淀进来（复盘环也会往这里补）。

写章程的规则：一条 = 一个可判定的检查。写不出"怎样算违反"的条目不要写。

---

## 模板 A：Web 服务 / API

```markdown
# 答辩章程：<项目名>

- C-01 未定义鉴权清单（谁能调哪些接口）= 硬伤
- C-02 无数据备份与恢复说明 = 硬伤
- C-03 接口无错误契约（状态码 + 错误体格式）= 硬伤
- C-04 写不出 `curl` 级验收的接口 = 硬伤
- C-05 敏感配置走环境变量而非落盘 = 检查项
- C-06 并发上限与过载行为（限流/排队/拒绝）未说明 = 硬伤
- C-07 日志可定位一次请求的全链路（有 trace id 或等价物）= 检查项
```

## 模板 B：CLI 工具 / 脚本

```markdown
# 答辩章程：<项目名>

- C-01 退出码语义未定义（0 成功 / 非 0 分类）= 硬伤
- C-02 无 `--help` 与版本号输出 = 硬伤
- C-03 破坏性操作（删除/覆盖）无确认或 `--dry-run` = 硬伤
- C-04 失败时无一行人话错误（指明哪个文件哪一步）= 硬伤
- C-05 依赖未声明或与系统包冲突未说明 = 检查项
- C-06 不能一条命令安装/运行 = 检查项
```

## 模板 C：游戏 / 实时交互

```markdown
# 答辩章程：<项目名>

- C-01 目标帧率预算未写（最低机型 + 目标 fps）= 硬伤
- C-02 主循环里每帧分配/IO 未受控 = 硬伤
- C-03 无存档/进度损坏的恢复策略 = 硬伤
- C-04 输入延迟预算未定（输入→画面响应上限）= 检查项
- C-05 帧率/内存的度量方式写不出命令或观察步骤 = 硬伤
- C-06 目标平台最低配置假设未登记为 A-xx = 硬伤
```

## 模板 D：空白（自定义领域）

```markdown
# 答辩章程：<项目名>

- C-01 <本领域不写清就必然返工的事实> = 硬伤
- C-02 <第二容易翻车的点> = 硬伤
- C-03 <度量方式> = 检查项
```
