# 论文模板与编号规范（thesis-template）

写论文前读本文件。产出 `docs/thesis.md`。

## frontmatter（必备，恢复与门禁都靠它）

```yaml
---
project: <项目名>
version: 1            # 每次修订 +1；回炉重辩出口同样 +1
status: draft         # draft → defending → passed | conditional；回炉重辩 → redefending → passed | conditional
phase: idle           # questioning | answering | reviewing | idle（轮内阶段，每阶段完成即落盘，断点恢复依据）
depth: 标准           # 轻量 | 标准 | 严酷（拨盘结果，恢复时不重问）
rounds: 0             # 已完成的有效轮数（每轮复审落盘时主代理 +1）
redefense-of: CR-xx   # 可选：进入回炉重辩时写入，终态保留（施工侧复工锚点之一）
date: <YYYY-MM-DD>
---
```

## 七章结构（章固定，内容随项目）

```markdown
# <项目名> 立项论文 v<n>

## §1 问题与目标
要解决什么问题、为谁解决、成功的判据。每个目标一条 P-xx。

## §2 方案总览
做什么、怎么做、整体结构。分小节叙述，关键主张落在条目编号上。

## §3 关键决策与被否替代方案
每个技术/产品决策一条 D-xx：决策内容 / 理由 / 被否的替代方案及否决原因。

## §4 假设清单
每条 A-xx 三选一标注：
- [已验证] 附证据（命令输出、文档链接、实验结果）
- [待验证] 施工 S0 步将验证（→ 施工 skill 会把它变成 S0 技术验证步）
- [纯假设] 说明为何即使不验证也可接受

## §5 风险与失败模式
每条 R-xx：风险 / 触发条件 / 缓解措施 / 回退方案。答辩中被豁免的软伤也登记到这里。

## §6 验证计划
每条 V-xx 对应一个可执行命令或可观察结果（例：`npm test`、`curl /health 返回 200`、`帧率 ≥ 60`）。施工 skill 会把 V-xx 直接变成计划步骤的验收命令。

## §7 边界与非目标
明确不做什么（B-xx），防止范围蔓延；导师攻击越界时学生以此自辩。

## §8 已接受风险（答辩通过后由软伤沉淀而来）
每条 = 软伤描述 + 导师意见 + 接受理由。施工 skill 开工时会读取本章注入注意事项。

## 修订记录（changelog）
| 版本 | 轮次 | 变更摘要 |
|---|---|---|
| v1 | - | 初稿 |
| v2 | 1 | D-02 补充基准数据；A-03 改判待验证 |
```

## 编号规范（全文追溯链的起点）

| 前缀 | 含义 | 下游消费者 |
|---|---|---|
| P-xx | 目标 | 施工完工对照表 |
| D-xx | 决策 | 计划步骤的"做法约束" |
| A-xx | 假设 | 待验证 → 施工 S0 技术验证步 |
| R-xx | 风险 | 计划步骤的回退方案 |
| V-xx | 验证 | 计划步骤的验收命令 |
| B-xx | 边界 | 计划的"不做清单" |

编号一经分配不复用、不重排；条目作废时保留编号并标记 [作废]，被 CR-xx（施工变更单）替代。

## 存量文档迁移（已有方案/论文接入）

已有较完整的项目方案文档（往往自带编号体系，如 RQ / FR / NFR / ADR）接入答辩时：

1. 复制为 `docs/thesis.md`，**原文不重排、不改写**；顶部插入 frontmatter（version 从接入版的下一版起算，status: draft）。
2. 文首加 §0《编号对照表》：把原文编号映射到本模板的语义角色（P-目标 / D-决策 / A-假设 / R-风险 / V-验证 / B-边界）。导师提问按对照表引用原编号即可定位；同义编号（如 FR 表的"验证方式"列对应 V 类）必须显式声明。
3. 原文档中的"待验证项 / 可行性前提"类条目，判定时一律按 **A-xx 假设（待验证态）** 对待；其附带的回退路径视为预案，不豁免验证义务。
4. 自接入版本起遵守本模板写作纪律：每轮只修订被攻击的章节，并在修订记录补一行。
5. 迁移不改变停机规则：严酷档 5 轮上限、0 硬伤通过，与全新论文一致。

## 写作纪律

- 论断要么给证据，要么登记为 A-xx 假设，要么落为 R-xx 风险——不许裸奔。
- 篇幅以"讲清"为准，禁止凑字；导师不评审文采。
- 学生修订时只改被攻击的章节与 changelog，不许顺手大改无关内容（防修订引入新硬伤且难以复审）。
