## Finding fixed during WP6 (BOM)

PowerShell `Set-Content -Encoding UTF8` wrote a UTF-8 BOM into
`runtime-policy.json`; strict `utf-8` parsing rejected it (fail-closed, as
intended). The run itself diagnosed and stripped the BOM to proceed, and the
engine now reads policy/gate/trace sidecars with `utf-8-sig` so a BOM alone
no longer blocks a legitimate file. Wrong-schema or corrupt sidecars still
fail closed.
